# HANDOFF.md — точка входа для нового чата

Читается **после** `project.md` и `design.md` и **до** любых изменений. Задача — быстро ввести в курс, не переизобретать утверждённое и не выдавать желаемое за готовое.

## 1. Где мы сейчас

- **Продукт:** Fate Core Character Service — лист персонажа, список, конструктор, печать, аккаунт и обмен за столом. React + TypeScript + Vite, Firebase (Auth + Firestore), PDF в браузере (`pdf-lib`). Живёт на GitHub Pages: https://danchel77.github.io/fate-core-sheets/
- **Адреса:** `#/` — список + вкладка «Группа»; `#/hero/<id>` — лист; `#/new` — конструктор; `#/s/<код>` — чужой лист по ссылке; `#/g/<код>` — вход в группу; `#/group` — группа за столом; `#/group/hero/<uid>` — чужой лист в группе с заметками.
- **Собрано и утверждено:**
  - лист-фолиант (две страницы с V-ложбинкой, пачка листов, кожаная обложка), темы «Ведьмак» и Fate через `data-theme`, печать A4 ч/б;
  - список: карточки-экслибрисы, эмблема сеттинга, фильтры/поиск/сортировка, импорт, «Создать героя» в шапке;
  - конструктор: 4 шага, справки, генератор имён, сохранение при закрытии;
  - аккаунт: Google и почта; герои в `users/{uid}/heroes`, без входа — IndexedDB; перенос героев при первом входе;
  - обмен: ссылка на лист, группа (до 12 групп, «Мастер игры», приглашение, мастер убирает игрока и закрывает), заметки на блоках чужого листа; чужой лист — строго без правок (крестики, подъём и пустые слоты навыков скрыты), окно заметок — на общем каркасе приложения; с чужого листа в группе работает «Экспорт» — JSON, PDF и PNG, без пункта «Поделиться ссылкой» (в картинку не попадают заметки и знаки их добавления);
  - предрелизная гигиена (2026-11-21): убраны дубли и мёртвый код, сведены повторы CSS, PDF грузится только при экспорте (стартовый JS 836 → 323 КБ gzip), локальная запись с паузой, портрет ограничен 700 КБ, битая ссылка не роняет страницу, ошибки показываются плашкой, есть страховка от падения экрана;
  - скачивание листа (2026-11-22): «Экспорт» → «Скачать лист» открывает окно с двумя вариантами — бумажный PDF или PNG-разворот книги (обложка, ляссе, тень, прозрачный фон, без шапки, меню, пустых слотов, заполненных жетонов и отметок стресса); в окне есть превью обоих вариантов, поясняющих подписей нет. PNG — около 1 МБ (1,08×, ~1630×1140 px); PDF-превью кэшируется на запись, сборка начинается при открытии меню «Экспорт», а PDF.js и воркер подгружаются заранее: если меню открыто пару секунд, окно показывает бланк почти сразу (повторное открытие — ~0,1 с);
  - правила (2026-11-22, D99/D101): кнопка с иконкой раскрытой книги в тёмной шапке списка и в строке над книгой рядом с «Экспорт»; открывает большое окно с вкладками «Игроку» и «Мастеру» — общая шпаргалка по Fate и «Ведьмаку» (4 + 4 раздела, таблицы на телефоне карточками). Первый раздел объясняет проверку словами и заканчивается списком исходов, без таблицы «Лестница»; термины — существующие подсказки `Hint` по маркеру `{{термин}}`, без словаря в начале. Текст — в `src/data/rules.ts`, окно — `RulesDialog`.
  - проверка ИИ (2026-11-24, D106/D108/D109/D110): в конструкторе одна компактная кнопка «✦ Проверить» (32 px на ПК, 38 px на телефоне) стоит справа в строке с подсказкой «Как придумать…»; в её шевроне — «⧉ Промпт», тот же промпт без JSON для ручной проверки, при исчерпанной квоте остаётся один чип «⧉ Промпт». На шаге 2 одна кнопка проверяет все три свободных аспекта одним запросом, на шаге 4 — все трюки: общая оценка и вердикт, правка на каждый заполненный элемент и по два варианта на пустые (у трюка вариант — название и эффект; варианты только показываются, вставить по клику нельзя). Контекст по видам: концепция — сама по себе, проблема — только с концепцией, аспекты и трюки — с концепцией и проблемой. Ответ — карточка с оценкой 1–5, двумя «что хорошо» и двумя правками «что не так — готовая замена», без автозамены; только после входа, один запрос за раз. Модель — `gemini-4-hydrogen` (thinking MEDIUM) через Firebase AI Logic, ответ — строгий JSON; App Check настроен. Промпт у каждой проверки свой: общими остались роль и шкала 1–5, дальше — определение из правил, признаки хорошего и слабого варианта и примеры из подсказок конструктора; встроенная проверка получает тот же бриф и возвращает строгий JSON по своей схеме (у концепции поля «пересечение» нет), ручная — обычный текст по шаблону, пункты с новой строки и без нумерации. Бесплатный тариф Google — 20 запросов в сутки на проект и модель; при 429 интерфейс запоминает сброс и возвращается сам.
- **Навыки:** в «Ведьмаке» 18 пересобранных навыков — «Ловкость» вместо «Атлетики», «Ближний бой» вместо «Драки», раздельные «Обман» и «Провокация», «Скрытность» вместо «Воровства»+«Скрытности». В классическом Fate — официальные 18 имён. Старые листы читаются через переносы имён; при слиянии Воровства и Скрытности остаётся большее значение, разница уходит в свободные очки. На листе наведение на навык показывает описание, клик открывает замену только на свободный навык (на телефоне — первое касание описание, второе замена).
- **Не сделано:** четвёртый слот последствия, когда нужный навык доходит до +5; отдельное хранилище портретов; прототип TableTop Simulator.
- **Ждёт пользователя:** правила `notes` и `groupLinks` опубликованы и проверены на живом сайте 2026-11-21. Для ИИ включены AI Logic и App Check, переменная сборки `VITE_APP_CHECK_SITE_KEY` задана; бесплатный лимит Google — 20 запросов в сутки на проект и модель, при исчерпании интерфейс предлагает копирование промпта.

## 3. Жёсткие правила

- **Утверждённое не переизобретается.** Палитра, шрифты, токены, компоновка листа, список и карточки, окно конструктора — заморожены; менять только по прямой просьбе.
- **Продуктовые решения — не молча.** 1–3 вопроса пользователю, по-русски, без техножаргона. Внешний вид нового экрана/крупного элемента — 3 временных варианта в реальном масштабе, показ, выбор, удаление временного (кроме шагов конструктора — они собираются в продакшене).
- **Новые маршруты, хранилища, сторонние библиотеки, анимации** — только по решению пользователя.
- **Цвета и шрифты** — только из `src/styles/tokens.css`. Никаких hex/rgba и `font-family` вне него.
- **Простые функциональные иконки** (стрелки, крестики, лист заметки) можно рисовать SVG-кодом; сложный декор — только скачанные ассеты с лицензией в `public/assets/CREDITS.md`.
- **Временные страницы сравнения** (маршрут, CSS, данные) удаляются после выбора; постоянных тестовых страниц нет.
- **Не выдавай желаемое за реализованное.** Перед «готово» — сборка, проверка в браузере, живой сайт.

```

                               options), CharacterWizard, NameGenerator, notes/
src/ai/                      — review (промпт, вызов Gemini, ручной промпт), quota (общий store квоты)
src/data/                    — types, characters (правила/пирамида), rules (текст окна правил), token, storage (IndexedDB), store (local/cloud),
                               cloud (Firestore heroes/share), groups (группы, заметки, карточки),
                               exchange (файл героя), skillMigration (старые имена навыков), settings/ (навыки, подсказки и имена сеттингов)
src/firebase/                — config, app, authStore
src/pdf/                     — fonts, sheetPdf
src/styles/                  — tokens.css (единственный источник), characters, sheet, wizard, notes, group, rules…
src/data/settings/           — конфигурации сеттингов: skills, народы, имена, королевства
```

- `SheetScreen` собирает лист из блоков; каждая правка уходит в `onPatch` → `updateCharacter` (сразу, без кнопки «Сохранить»).
- `store.ts` — режимы local/cloud, подписка `useSyncExternalStore`, дебаунс записи в облако 700 мс, перенос героев при входе.
- `groups.ts` — `users/{uid}` = `{ groups: [{ id, name, heroId }] }`; `groups/{id}`, `groups/{id}/members/{uid}`, `groups/{id}/notes/{noteId}`, `groupLinks/{token}`.
- Внутри `fieldset.sheet-lock` (чужой лист) кнопки отключены — интерактивные знаки заметок сделаны `span` с `role="button"`.

## 5. Данные и правила Firestore

Правила — разовая настройка в консоли Firebase (в репозиторий не попадают). Полный набор:

```
match /users/{uid}/heroes/{heroId} {
  allow read, write: if request.auth.uid == uid;
}
match /shared/{token} {
  allow read: if true;
  allow create: if request.auth != null;
  allow update, delete: if request.auth != null
    && resource.data.owner == request.auth.uid;
}
match /groups/{groupId} {
  allow read: if request.auth != null;
  allow create: if request.auth != null;
  allow update, delete: if request.auth != null && resource.data.masterId == request.auth.uid;
  match /members/{uid} {
    allow read: if request.auth != null;
    allow create, update: if request.auth != null && request.auth.uid == uid;
    allow delete: if request.auth != null && (request.auth.uid == uid
      || get(/databases/$(database)/documents/groups/$(groupId)).data.masterId == request.auth.uid);
  }
  match /notes/{noteId} {
    allow read: if request.auth != null;
    allow create: if request.auth != null && request.resource.data.authorId == request.auth.uid;
    allow update: if request.auth != null && resource.data.authorId == request.auth.uid;
    allow delete: if request.auth != null && (resource.data.authorId == request.auth.uid
      || get(/databases/$(database)/documents/groups/$(groupId)).data.masterId == request.auth.uid);
  }
}
match /groupLinks/{token} {
  allow read: if true;
  allow create: if request.auth != null;
  allow update, delete: if request.auth != null
    && resource.data.masterId == request.auth.uid;
}
match /users/{uid} {
  allow read, write: if request.auth.uid == uid;
}
```

- `users/{uid}` — документ-указатель (список групп и герой за столом). Путь `users/{uid}/group` — нечётное число сегментов, Firestore на нём падает; не возвращать.
- Без правил `notes` сохранение заметки даёт «Не получилось сохранить заметку…». Это настройка проекта, а не сбой интерфейса.
- `groupLinks` обновлено, опубликовано и проверено 2026-11-21: менять и удалять приглашение может только мастер группы (`masterId`). Проверка: мастер меняет свою ссылку, второй аккаунт получает «Missing or insufficient permissions».
- Состав и заметки группы по-прежнему читает любой вошедший, кто знает id группы (id приходит в ссылке-приглашении). Это оставлено осознанно: приглашённый должен видеть, куда идёт; отдельного решения о закрытии чтения не было.

## 6. Грабли, которые кусают

- **Токены** — единственный источник цвета и шрифтов; не хардкодить.
- **Окна** — все через `useDialogKeys` и `useBodyScrollLock`; слои: конструктор 300, окна/подтверждения 320, выбор навыка 340, портрет 360, подсказки 400.
- **Изменения списка** — карточки в `characters.css` общие для вкладок; не копировать их в новый компонент.
- **CSS всех окон** импортируется глобально в `main.tsx` (`.sm__*` в `stunt-modal.css`), поэтому окна можно собирать в любом месте без локальных стилей шапки.
- **Пуш** — `GIT_TERMINAL_PROMPT=0 git -c credential.helper= push origin main` (обычный падает на кэше учётных данных в песочнице).
- **Проверки** — `PLAYWRIGHT_BROWSERS_PATH="$PWD/.scratch/pw-browsers"`, `deviceScaleFactor: 1`, экраны 360/768/1024/1440/1920, скриншоты 1:1 в `.scratch/` (в git не входят), после проверки гасить preview/dev.
- **Тестовые аккаунты** — `qa.sheets.20261120@example.com` и `qa2.sheets.1795206822134@example.com` (реальные записи в Firebase проекта пользователя). Пароль в репозитории не хранится: при надобности сбросить его в консоли Firebase. После сценариев группы закрывать.
