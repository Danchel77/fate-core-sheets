# HANDOFF.md — точка входа для нового чата

Этот файл читается **после** `project.md` и `design.md` и **до** любых изменений. Его задача — быстро ввести в курс дела, сохранить утверждённый визуальный язык и не выдавать несуществующее за готовое. Дизайн нового экрана — ожидаемая работа: его нужно предложить вариантами, а не копировать лист. Исключение — окно конструктора: его шаги собираются прямо в продакшене (§3).

## 3. Жёсткие правила, чтобы не «изобретать»

- **Утверждённый лист заморожен.** Палитра, шрифты, заголовки, компоновка листа, блоки и токены не пересматриваются без прямой просьбы пользователя. Новый экран — не «переизобретение»: его компоновка, карточки и новые компоненты проектируются заново в утверждённом языке.
- **Продуктовые решения — не молча.** Открытый вопрос о поведении, объёме, хранении, маршруте или функции закрывается 1–3 вопросами пользователю. Внешний вид нового экрана решается иначе: покажи 3 временных варианта и дай выбрать (кроме окна конструктора — см. следующий пункт). «Не придумывай „красиво“ молча» означает «не выпускай в продакшен без выбора», а не «не предлагай варианты».
- **Окно конструктора — исключение из «трёх вариантов».** Пользователь запретил макеты шагов (m01609, m03223): общий каркас утверждён (D48), каждый шаг собирался сразу в продакшене и доводился по замечаниям. Конструктор собран; это правило больше к нему не применяется, но остаётся в истории решений.
- **Новые страницы, маршруты, хранилище, библиотеки и анимации не добавляются** без решения в `project.md`. Экран, который пользователь прямо заказал (следующий — печать), уже разрешён к дизайну и необходимым компонентам; новые маршруты, хранение и сторонние библиотеки всё ещё требуют отдельного решения.
- **Печать опирается на утверждённый скелет** (D21) и собрана в PDF (D58): A4 горизонтально, повторяет официальный бланк, в правом верхнем углу официальный логотип Fate Core. Портрет на печать не выводится — так решил пользователь.
- **Временные страницы сравнения.** Для нового элемента можно сделать 3 варианта на отдельной странице, показать **в реальном масштабе** и после выбора удалить страницу, её CSS, маршрут и тестовые данные.
- **Никаких постоянных тестовых страниц** (`src/preview`, `#test`, `#variants` и т. п.) в финале.
- **Не подменяй факты.** Перед ответом «готово» проверь код, сборку и живой сайт.
- **Пользователь — не программист.** Вопросы и объяснения — коротко, по-русски, без технического жаргона.

## 4. Архитектура в двух словах

```
src/App.tsx                    → hash-адреса: #/ → CharactersScreen, #/hero/<id> → SheetScreen, #/new → NewCharacterScreen
src/screens/CharactersScreen.tsx → список: тулбар, карточки, удаление с подтверждением, пустое состояние
src/screens/SheetScreen.tsx    → собирает лист из блоков героя, правки уходят в onPatch
src/screens/NewCharacterScreen.tsx → пустой лист + конструктор; при закрытии окна создаёт запись и открывает лист
src/components/CharacterWizard.tsx → окно конструктора: шаги 1–4, справки, выбор навыка, подвал
src/components/SkillPyramid.tsx → пирамида 4/3/2/1: карточки, крестики, пунктирные слоты (лист и конструктор)
src/components/SkillPicker.tsx  → общее окно выбора навыка (конструктор и лист)
src/components/ConfirmDialog.tsx → подтверждение удаления героя
src/components/                → блоки листа, карточка списка, SettingMark, иконки
src/data/types.ts              → типы: Character, Aspect, Stunt, LadderRow, StressMarks, CharacterRecord, CharacterPatch
src/data/characters.ts         → SKILLS, stressCells, physicalStress/mentalStress, effectiveRefresh, ladderFromPicks, createEmptyCharacter
src/data/storage.ts            → IndexedDB через idb: readAll, writeOne, removeOne, newId; запасной Map, если база недоступна
src/data/store.ts              → подписка useSyncExternalStore, loadCharacters, findCharacter, createCharacter, updateCharacter, deleteCharacter
src/data/skills.ts             → SKILL_HINTS: одна строка о каждом навыке
src/pdf/fonts.ts               → встраивание Montserrat в PDF (fontkit, подмножества)
src/pdf/sheetPdf.ts            → сборка печатного бланка: геометрия официального листа, усадка текста, лист «Продолжение"
src/styles/tokens.css          → единственный источник цветов, шрифтов и размеров
src/styles/characters.css      → стили списка
src/styles/wizard.css          → стили окна конструктора
src/styles/skill-picker.css    → стили окна выбора навыка
```

- `StuntBlock` и `StuntModal` — только лист; в конструкторе свои поля трюков внутри `CharacterWizard`, их не путать.
- `CharacterBlock` принимает `character: Character`; блоки получают начальные значения пропсами и держат собственное состояние, а каждую правку отправляют наверх (`onPatch` / `onChange`). `SheetScreen` передаёт правку в `updateCharacter` — запись пишется сразу, без дебаунса.
- При переключении персонажа `App` монтирует `SheetScreen` с `key` по `id`, иначе поля останутся от предыдущего героя.
- `CharacterRecord` — `{ id, setting, createdAt, updatedAt, sheet }`; `name`, `concept`, `level`, `portrait` для карточки берутся из `sheet`. Если имени нет, карточка подписана «Безымянный герой».
- Список читает записи один раз при открытии (`loadCharacters`) и дальше живёт на подписке.
- Список запоминает фильтр сеттинга и сортировку в `localStorage` (ключ `fate-core-sheets:list-view`); поиск не запоминается.
- Старые хэш-страницы удалены; незнакомый адрес показывает список.
- `#/new` держит черновик в состоянии `NewCharacterScreen`; лист под окном перерисовывается на каждый ввод, после сохранения открывается уже сохранённый лист. Пустой черновик не пишется в базу — человек возвращается к списку.
- PDF собирается целиком в браузере: `downloadPdf` в `CharactersScreen` → `buildCharacterPdf` (`src/pdf/sheetPdf.ts`) → Blob → скачивание. Шрифты лежат в `public/fonts/`, логотип — `public/assets/logos/fate-core-logo.png`. Ссылки на готовый файл нет: она требует хостинга.
- `Hint` (`src/components/Hint.tsx`) — единственный источник подсказок-терминов: линия 1 px в 1 px под словом, плашка по наведению с задержкой 200 мс, фокус и клик открывают сразу.
- Слои окон: конструктор — 300, окно трюка и подтверждение — 320, выбор навыка — 340, портрет — 360, подсказки — 400. Не понижать: окно трюка из конструктора должно быть выше него.

- Шаг 4 «Трюки»: две колонки 260 px / остальное — слева короткое пояснение, справа карточки трюков (без панели листа и окна трюка). ### Технические грабли
- **Пустой черновик.** `isBlankDraft` в `NewCharacterScreen`: без имени, текстов, навыков, трюков и портрета запись не создаётся. Пустые карточки трюков отбрасывает `filledStunts`. Не убирать — иначе случайно открытое окно плодит пустые карточки.
- **Хранилище.** `src/data/storage.ts` при недоступной базе тихо переходит на `Map` в памяти (без предупреждений в консоль). `store.ts` публикует новое состояние до записи, поэтому интерфейс не ждёт базу.
- **Портрет** хранится data URL (JPEG 600×800) внутри листа и не попадает в файл героя (T12, T5).
- **Стресс.** `stressCells` в `src/data/characters.ts`: навык +3 и выше — 4 ячейки, +1/+2 — 3, иначе 2. Дополнительный слот «Лёгкое последствие» при +5 пока не реализован — известное ограничение, не выдавать за готовое.
- **Обновление.** `effectiveRefresh`: три трюка бесплатны, каждый следующий снимает жетон, но не ниже 1. В окне трюка предупреждение считается той же формулой.
- **Состояние блоков.** Блоки не синхронизируются с props: правка идёт через `onChange`, а сохранённое значение приходит уже после записи. `SkillsEditor` сам ведёт пирамиду и уровень.
- **Слои окон.** Окно трюка было с z-index 260 и уходило под окно конструктора (300) — поднято до 320. При новых окнах сверяйся с лестницей слоёв в §4.
- **Мобильный шаг 4.** Две колонки шага «Трюки» включаются только `@media (min-width: 761px)`: правило, дописанное после мобильного медиа-запроса, иначе перебивало одноколоночную раскладку.
- **Шаг 4 и высота.** Пока трюков меньше четырёх, справка ужимается до 424 px и прокручивается сама — тело окна без полосы; класс `wiz__stunt-help--scroll` ставится по числу карточек, не убирать, иначе снова появятся две полосы. Не увеличивать карточки и плитку без замера `.scratch/measure-step4.mjs`: ссылка «Как придумать трюк» должна оставаться видимой.
- **Esc и подсказка.** `Hint` при Escape вызывает `stopPropagation`, иначе подсказка-термин закрывала всё окно конструктора.
- **Роутер** — самодельный разбор хэша в `src/App.tsx`; библиотеку не ставим.
- **Не возвращай удалённые тестовые страницы**; временные файлы держи в `.scratch` и удаляй.

- **Playwright**: `PLAYWRIGHT_BROWSERS_PATH="$PWD/.scratch/pw-browsers"`, `deviceScaleFactor: 1`, пауза ≥ 300 мс после открытия окна (анимация 180 мс). На `#/new` под окном рендерится лист — клики ограничивать `.wiz-overlay`, иначе их перехватывают слоты листа.
- **IndexedDB в проверках**: каждый запуск Playwright — чистый профиль, поэтому героев нет. Создавай их в том же запуске; перезагрузка страницы (`page.reload()`) профиль сохраняет.
- **Push**: `GIT_TERMINAL_PROMPT=0 git -c credential.helper= push origin main` — обычный падает на кэше учётных данных в песочнице. После push GitHub Pages 45–60 с отдаёт 503; проверять `web_fetch` файла бандла, взятого из `dist/index.html`.
- **Снимки**: только 1:1, временные файлы — в `.scratch/`, в git не попадают.
