## 3. Жёсткие правила, чтобы не «изобретать»

- **Утверждённый лист заморожен.** Палитра, шрифты, заголовки, компоновка листа, блоки и токены не пересматриваются без прямой просьбы пользователя. Новый экран — не «переизобретение»: его компоновка, карточки и новые компоненты проектируются заново в утверждённом языке.
- **Продуктовые решения — не молча.** Открытый вопрос о поведении, объёме, хранении, маршруте или функции закрывается 1–3 вопросами пользователю. Внешний вид нового экрана решается иначе: покажи 3 временных варианта и дай выбрать. «Не придумывай „красиво“ молча» означает «не выпускай в продакшен без выбора», а не «не предлагай варианты».
- **Новые страницы, маршруты, хранилище, библиотеки и анимации не добавляются** без решения в `project.md`. Экран, который пользователь прямо заказал (сейчас — список персонажей), уже разрешён к дизайну и необходимым компонентам; маршруты, хранение и сторонние библиотеки всё ещё требуют отдельного решения.
- **Временные страницы сравнения.** Для нового элемента можно сделать 3 варианта на отдельной странице, показать **в реальном масштабе** и после выбора удалить страницу, её CSS, маршрут и тестовые данные.
- **Никаких постоянных тестовых страниц** (`src/preview`, `#test`, `#variants` и т. п.) в финале.
- **Не подменяй факты.** Перед ответом «готово» проверь код, сборку и живой сайт.
- **Пользователь — не программист.** Вопросы и объяснения — коротко, по-русски, без технического жаргона.

## 4. Архитектура в двух словах

```
src/App.tsx                    → hash-адреса: #/ → CharactersScreen, #/hero/<id> → SheetScreen
src/screens/CharactersScreen.tsx → список: тулбар, карточки, пустое состояние
src/screens/SheetScreen.tsx    → собирает лист из блоков выбранного героя
src/components/                → блоки листа, карточка списка, SettingMark, иконки
src/data/types.ts              → типы листа (Character, Aspect, Stunt, LadderRow)
src/data/characters.ts         → 9 демо-записей CharacterRecord, findCharacter(id)
src/data/demoCharacter.ts      → утверждённый демо-лист Геральта
src/styles/tokens.css          → единственный источник цветов, шрифтов и размеров
src/styles/characters.css      → стили списка
```

- `CharacterBlock` принимает `character: Character`; остальные блоки (`SkillsEditor`, `StuntBlock`, `StressBlock`, `ExtrasBlock`) получают начальные значения через props, но держат собственное состояние.
- При переключении персонажа монтируй лист/блоки с `key` по `id` (или сбрасывай состояние), иначе поля останутся от предыдущего героя. `FatePoints` уже сбрасывается по `initial`.
- `CharacterRecord` (список) — `{ id, name, concept, level, setting, createdAt, portrait?, sheet }`; лист — `Character` из `types.ts`. Это демонстрационная модель без хранилища; целевая — в `project.md` §5.2.
- Лист получает `character` пропом; при переходе к другому герою лист пересоздаётся заново, поэтому состояние полей не «переезжает».
- Список запоминает фильтр сеттинга и сортировку в `localStorage` (ключ `fate-core-sheets:list-view`); поиск не запоминается.
- Старые хэш-страницы удалены; незнакомый адрес показывает список.
