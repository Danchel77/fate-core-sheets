# PROJECT.md — Product Vision, Architecture & State

## 1. Product Overview
Веб-сервис для создания, хранения и печати листов персонажей НРИ по системе **Fate Core** (в духе сервиса *Long Story Short*, но с интерактивным конструктором, подсказками по правилам и печатным бланком 1-в-1).

Основной сценарий: игрок создаёт героя в конструкторе с подсказками, затем либо играет по веб-листу (отметки стресса, жетоны судьбы, последствия), либо распечатывает классический бланк для игры за столом.

### 1.1. Состав первой версии (MVP v1)
1. **Список персонажей** — карточки сохранённых героев, создание/удаление, выбор сеттинга при создании.
2. **Конструктор персонажа** — пошаговое создание: сеттинг → имя/описание → 5 аспектов → навыки (пирамида) → трюки → дополнения → портрет.
3. **Веб-лист** — умеренно интерактивный лист: стресс, жетоны судьбы, последствия, заметки.
4. **Печать и PDF** — печатный бланк A4 landscape, повторяющий официальный, и выгрузка векторного PDF.
5. **Экспорт/импорт персонажа в файл** — страховка от потери браузерных данных и перенос между компьютерами.

### 1.2. Отложено (v2+), не блокирует первую версию
- **Аккаунты и облако:** Firebase Auth (Google + Email/Password), Firestore, перенос локальных персонажей при входе.
- **Шеринг PDF по ссылке** через Firebase Cloud Storage.
- **ИИ-помощник (Gemini):** проверка аспектов и формулировки, помощь с трюками, концепция персонажа под сеттинг. Ключ — свой в настройках пользователя, плюс возможность вшить общий. Модель выбирается при подключении (кандидат — `gemini-3.5-flash-lite`, на 2026-11 помечена Stable).

## 2. Tech Stack & Infrastructure (LOCKED)

| Решение | Выбор | Почему |
|---|---|---|
| Frontend | React 19 + Vite + TypeScript | Модульность: одни и те же данные рисуются и в конструкторе, и в веб-листе, и на печати |
| Пакетный менеджер | `npm` (не Bun) | Совпадает с CI на GitHub Actions и стандартным окружением |
| Роутинг | `HashRouter` | GitHub Pages не умеет SPA-fallback без хаков с `404.html`; хэш-адреса работают всегда |
| Стили | Чистый CSS + CSS-переменные в `src/styles/tokens.css` | Единственный источник цветов и шрифтов; Tailwind дублировал бы палитру и нарушал правило «ноль hex вне tokens.css» |
| Хранение v1 | IndexedDB (библиотека `idb`) за интерфейсом `CharacterStorage` | Большая квота, бинарные портреты без base64; тот же интерфейс потом реализует Firestore-адаптер |
| PDF | `pdf-lib`, векторный PDF, встроенный кириллический TTF (OFL) | Единственный способ получить настоящий вектор и файл для будущего шеринга |
| Хостинг | GitHub Pages, деплой через GitHub Actions | Бесплатно, публичный репозиторий |
| Отложено | Firebase Auth / Firestore / Storage, Gemini API | MVP не требует сервера и аккаунтов |

Секретов в клиентском бандле нет: ИИ-ключ в v1 отсутствует, а общий ключ при подключении ИИ будет осознанным решением с ограничением по referrer.

## 3. Core Features & Domain Rules
Полные правила, списки навыков по сеттингам и критерии аспектов — в `fate_core_rules.md`. Ключевое:

- **Сеттинги:** «Классический Fate Core», «Ведьмак», «Базовый D&D». Выбор фиксируется при создании персонажа и **не меняется** потом.
- **18 навыков в каждом сеттинге** — ровно 18, адаптация через слияния/замены, без добавления «лишних» пунктов.
- **Магия** доступна всем персонажам без проверок аспектов (ограничения — вопрос отыгрыша).
- **Пирамида:** заполнение строго снизу вверх; верхняя ступень заблокирована, пока не заполнена нижняя; дополнительные навыки +1 сверх четырёх допустимы с предупреждением.
- **Дополнения (Extras):** одно свободное текстовое поле и в вебе, и на печати.
- **Стресс:** число ячеек выводится из Телосложения и Воли (2/3/4), отметки ячеек — состояние персонажа, сохраняются вместе с ним.
- **Последствия:** Лёгкое 2 / Среднее 4 / Серьёзное 6 + дополнительный слот «Лёгкое» при навыке +5 (из правил).
- **Портрет:** загрузка файла с компьютера, кадрирование и масштабирование внутри рамки.

## 4. Target Screens
1. **Список персонажей** — карточки, фильтр по сеттингу, «Создать», экспорт/импорт.
2. **Конструктор** — пошаговый мастер с подсказками из `fate_core_rules.md`; работает и на телефоне (полноценно, включая мастер).
3. **Веб-лист** — пергаментная книга на тёмном столе; интерактив: стресс, жетоны судьбы, последствия, заметки.
4. **Печатный лист** — A4 landscape, чёрно-белый, повторяет официальный бланк; заголовок нейтральный («Fate Core» текстом), без официального логотипа-торговой марки.

## 5. Data Model (v1)

```ts
type Setting = 'core' | 'witcher' | 'dnd';

interface Character {
  id: string;                 // crypto.randomUUID()
  schemaVersion: 1;
  setting: Setting;           // фиксируется навсегда
  name: string;
  description: string;
  aspects: {
    highConcept: string;      // Ключевой аспект
    trouble: string;          // Проблема
    phaseOne: string;         // Первое приключение
    phaseTwo: string;         // Переплетение судеб 1
    phaseThree: string;       // Переплетение судеб 2
  };
  skills: Record<string, number>;   // только ненулевые, max 10 записей
  stunts: string[];                 // 3 бесплатных + до 2 доп.
  extras: string;                   // «Дополнения», одно поле
  consequences: { mild: string; moderate: string; severe: string; extraMild: string };
  stress: { physical: boolean[]; mental: boolean[] };  // отмеченные ячейки
  fatePoints: number;
  portrait?: { key: string; crop: { x: number; y: number; scale: number } };
  createdAt: string;          // ISO
  updatedAt: string;          // ISO
}
```

- Экспорт — файл `*.fate.json`: `{ schemaVersion, exportedAt, character }`. Импорт валидирует `schemaVersion` и создаёт нового персонажа с новым `id`, если такой уже есть.
- Портреты хранятся отдельно от JSON (Blob в IndexedDB), в экспорт не попадают; при импорте рамка остаётся пустой, пока не загрузят фото.

## 8. Constraints & Risks
- **Товарный знак:** официальный логотип FATE CORE SYSTEM (™) не используется; на печати — нейтральная надпись текстом.
- **Лицензии ассетов:** только CC0 / OFL / public domain или явно разрешённые; каждый ассет фиксируется в `public/assets/CREDITS.md` (источник, автор, лицензия).
- **Нет сервера:** всё считается на клиенте; никаких секретов в бандле.
- **Точность печати:** сверка с официальным бланком входит в Definition of Done для печатного экрана (см. `AGENTS.md` §5).
- **Потеря данных:** без экспорта файла чистка браузера уничтожает героев — поэтому экспорт/импорт обязателен в v1.
