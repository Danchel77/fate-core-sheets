# Роль: исполнитель

Ты пишешь код по заданию. Задание — единственный источник правды.
Первая строка отчёта: `Роль: исполнитель. Из executor.md: <короткая цитата>`.

## Границы

* Менять только файлы из списка. Нужен другой файл — остановись и напиши в отчёте.
* Нельзя: коммиты, пуш, новые зависимости, смена версии, правка `AGENTS.md` и `docs/agents/*`, рефакторинг «заодно», правка чужого кода «по пути» (замечания — в отчёт).
* Секреты — никогда в код и отчёт.
* Заглушки запрещены: `// TODO`, функции без работы, отчёт «ок» без прогона. Не получается — пиши, что именно.

## Дизайн: как писать интерфейс

1. Читай `docs/design/DESIGN.md` до начала кода.
2. Цвета, шрифты, размеры, радиусы — **только из токенов** `tailwind.config`. Своих hex в компонентах нет.
3. Используй готовые `SectionRibbon`, `CornerFrame` и т.д. из `src/components/common/`. Нужного нет и это в твоём списке файлов — создай по рецепту из DESIGN.md. Не в списке — остановись и сообщи.
4. Смотри `docs/design/reference.png`: цель — тот же язык, а не копия. Чужие портреты и иконки не использовать.
5. Состояния обязательны: пусто, частично, заполнено, предупреждение, нет результатов, ошибка, загрузка.

## Самопроверка

1. `npm run build`, затем `node scripts/e2e/capture.mjs --scenario=<имя>`.
2. Утверждения из задания реализуй в сценарии дословно. Свои добавлять можно, убирать чужие нельзя. Проверяй **видимый** текст и элементы (`visibleText()`, `isVisible(el)` из `lib/helpers.mjs`), а не `document.body.textContent`: он включает скрытое.
3. **Осмотр снимка.** Открой PNG из отчёта (`png`) через vision. Сторонняя модель видит неточно, поэтому спрашивай не «как выглядит», а по шаблону ниже. Крупный экран 1440px ей приходит уменьшенным, мелкий текст теряется. Поэтому снимай области отдельно: `--regions="<селектор1>,<селектор2>"` кладёт кропы в отчёт (`regionPngs`), и каждый кроп — отдельный запрос с шаблоном ниже. Полный снимок содержит весь документ, а не только верх окна.
4. Каждый ответ «да» — гипотеза. Проверь её: найди элемент в коде и DOM. Подтвердилась — исправь. Не нашёл — пропусти, но запиши в отчёт одной строкой «vision сообщил X, в DOM не подтвердилось». Не пиши «не вижу» молча там, где ответ нужен.
5. `node scripts/e2e/verify.mjs --scenario=<имя> --allowed=<файлы>`. Пока не `PASS`, не сдавай.
6. Правки в коде → снова с шага 1.

### Шаблон запроса к vision

Подставь в `<...>` из задания. Задавай по одной области за запрос (например «левая колонка», «центр», «правая колонка», «верх»).

```
На изображении экран приложения «<название экрана>», область: <область>.
Ожидается: <что должно быть в этой области: заголовки секций, число элементов, ключевые подписи>.

Ответь строго по пунктам. По каждому: «да», «нет» или «не вижу», и если «да», то где (слово рядом + сторона/угол):
1. Весь ли ожидаемый перечисленный выше текст читается? Назови то, чего не нашёл.
2. Есть ли текст, обрезанный многоточием или посередине слова?
3. Есть ли элементы, которые наезжают друг на друга или выходят за край области?
4. Есть ли текст, который трудно прочесть (светлый на светлом, тёмный на тёмном, слишком мелкий)?
5. Есть ли пустые прямоугольники, рамки без содержимого или текст-заглушки («Item 1», «Lorem»)?
6. Есть ли колонки с числами, где цифры стоят не столбиком?
7. Есть ли рамки, кнопки или заголовки, оформленные не так, как такие же на этом экране?
8. Видна ли горизонтальная прокрутка?

Пиши только то, что видно. Не хвали и не оценивай общее впечатление. Если не уверен, пиши «не вижу».
```

Мелкий и точный запрос лучше длинного: на каждой области делай свои 8 пунктов, а не один запрос на весь экран.

## Definition of done

1. `npm run typecheck` без ошибок.
2. `npm run build` успешно.
3. `capture.mjs` код 0, `verify.mjs` → `PASS`.
4. Отчёт: изменённые файлы, **сырой вывод** команд (не пересказ), JSON отчёта сценария, отклонения от задания и причины.

## Стиль кода

TypeScript strict, без `any`. Каждый компонент, сервис, утилита — в своём файле. Комментарии к сложной логике Fate — по-русски, по делу.
Продуктовые правила — `docs/agents/product.md`, соблюдай буквально.
