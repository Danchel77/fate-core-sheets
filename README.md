# Fate Core — листы персонажей

Веб-сервис для создания, хранения и печати листов персонажей по системе **Fate Core** и в антураже «Ведьмака»: список героев, пошаговый конструктор, живой лист-фолиант, печатный бланк A4, аккаунт и обмен за столом.

Сайт: https://danchel77.github.io/fate-core-sheets/

## Что умеет

- **Список героев** — карточки-экслибрисы, фильтры по сеттингу, поиск, сортировка, импорт и клонирование.
- **Конструктор** — четыре шага со справками, пирамида навыков, трюки, генератор имён, сохранение при закрытии.
- **Лист** — две страницы фолианта, темы «Ведьмак» и Fate, аспекты, стресс, последствия, трюки, дополнения; правки сохраняются сразу.
- **Правила** — кнопка-книга в шапке списка и листа открывает шпаргалку на две вкладки: «Игроку» и «Мастеру».
- **Печать и картинка** — ч/б PDF формата A4 (альбомная ориентация) по геометрии официального бланка, при нехватке места — лист «Продолжение»; или PNG-разворот книги без служебных кнопок и с прозрачным фоном.
- **Аккаунт** — вход через Google или почту; без входа герои лежат в браузере, после входа — в облаке.
- **Обмен** — публичная ссылка на лист только для чтения, группа за столом до 12 групп, приглашение по ссылке, заметки на блоках чужого листа. Лист игрока из группы можно скачать себе: «Экспорт» → JSON, PDF или PNG.
- **Проверка ИИ** — в конструкторе у концепции, проблемы, аспектов и трюков: оценка 1–5, две сильные стороны и два совета; без автозамены, один блок за раз, после входа. Бесплатный лимит Google — 20 запросов в сутки на проект и модель; при исчерпании остаётся кнопка «Скопировать промпт» с тем же заданием для ручной проверки.

## Стек

- React 19 + TypeScript + Vite 6, чистый CSS с токенами (`src/styles/tokens.css`).
- Firebase Auth и Firestore — вход и облачное хранение; Firebase AI Logic (`firebase/ai`) — проверка аспектов, `firebase/app-check` — защита запросов.
- `pdf-lib` + `@pdf-lib/fontkit` — сборка PDF в браузере; библиотеки грузятся только при экспорте.
- `html-to-image` — снимок разворота книги в PNG; грузится только при скачивании картинки.
- `pdfjs-dist` — показ страниц готового PDF в окне скачивания; грузится только при открытии окна.
- Публикация — GitHub Pages через GitHub Actions.

## Запуск

Нужен Node 22 (как в GitHub Actions).

```bash
npm ci           # установить зависимости по лок-файлу
npm run dev      # локальная разработка
npm run build    # проверка типов + сборка
npm run preview  # посмотреть собранную версию
```

## Данные

Без входа герои хранятся в браузере (IndexedDB). После входа список и правки идут в Firebase (`users/{uid}/heroes`), браузер остаётся офлайн-кэшем. Публичная ссылка показывает снимок листа; ссылка на приглашение ведёт в группу.

Правила доступа Firestore — разовая настройка в консоли Firebase, полный набор и пояснения — в `HANDOFF.md` §5.

## Проверка аспектов нейросетью

Карточка проверки уже в интерфейсе, но живой запрос включается настройкой проекта:

1. В консоли Firebase откройте **AI Logic** и включите Gemini API для проекта.
2. В **App Check** зарегистрируйте веб-приложение с провайдером **reCAPTCHA Enterprise** и скопируйте site key.
3. В GitHub: Settings → Secrets and variables → Actions → Variables → создайте `APP_CHECK_SITE_KEY` со значением site key.
4. Пересоберите сайт. Сборка передаёт ключ в `VITE_APP_CHECK_SITE_KEY`; без него запрос вернёт 403 и карточка покажет «Проверка пока не подключена».

На сервер уходят только тип проверки, сеттинг и тексты концепции, проблемы, непустых аспектов и трюка. Портрет, имя, навыки и другие данные не отправляются. Ключ Gemini хранится у Firebase, а не в коде сайта. Ответ 429 запоминается в браузере до сброса квоты; счётчика на сервере нет.
